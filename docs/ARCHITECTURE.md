# Architecture and upstream contract

The workbench is a companion to [Sebastian's SAST-Blackboard](https://github.com/U0iS112/654321). The Docker build checks out the configured `SAST_REF` commit into `/opt/sast` and installs the upstream pipeline dependencies listed in [`requirements-upstream-runtime.txt`](../requirements-upstream-runtime.txt). Compose publishes port 8031 on the host's loopback interface, keeps review data in a named volume, and runs with a read-only container filesystem. Updating Sebastian's source means selecting a newer reviewed commit and rebuilding the image.

The workbench calls the original `blackboard.codebase.core.blackboard_semantic_mapping.run_pipeline` in a child process. It supplies the upstream `datacorpus/vcslam` path, sample IDs, historical IDs, a workbench-owned output directory, and `run_evaluation=False`. The worker then imports the generated `*_mapping_results.json` files. This keeps mapping behavior in Sebastian's repository while the workbench owns execution controls, display, and later review. An upstream change to the function signature or output format requires an adapter or worker update here.

`adapter.normalize` maps each SAST result into attribute items. IDs are derived from attribute names; candidate IDs are derived from validated mapping strings. Each item retains the original machine mapping, matrix, complete state, and logs. `runs.raw` stores imported machine output in full with a SHA-256 hash. Runs started by the workbench also include an added `workbench_context` field with source data and execution metadata; the original SAST fields are retained. Human review never updates `runs.raw`.

`Store` uses SQLite transactions. `items.version` starts at 1 and increments when a human decision is saved. `events` append posts, replies, agent responses, and decisions against an item version. `parent` identifies replies, and candidate IDs link posts to recorded validated candidates. Stale decisions return HTTP 409. Agent posts carry model and prompt metadata; they cannot change human decisions or machine output.

The **Original council record** is read from Sebastian's `discussions` export. The optional workbench **bounded agent review** is a separate two-role sequence that reads recorded context and posts advisory responses. It is not another execution of Sebastian's original council and cannot approve a mapping. Both remain distinguishable in the UI and exported review bundle.

The HTTP server accepts only localhost Host values for its published port and checks request Origin; mutations require a per-server token. Reviewer names are self-declared. The Compose port mapping restricts host access to `127.0.0.1:8031`. Saved runs, discussions, decisions, and job files stay in the local Compose volume. Configured model jobs send selected context to the provider; importing and inspecting existing runs does not.

See [the original workflow guide](ORIGINAL_WORKFLOW.md) for the correspondence between SAST stages and UI panels, and the [README](../README.md) for operation and version updates.
